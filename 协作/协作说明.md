# 协作说明（本系统的“宪法”）

## 三个角色

- **人类**：定目标、批准、验收；不写代码。
- **AI-A（架构/审查）**：审阅 reviewer 角色绑定的 Agent 写入的 `项目/<编号>_<短名>/对接/审查.md`；不得以 `AI-A` 名义代写审查文件（新审查必须署名为 reviewer 角色 + Agent ID）。
- **AI-B（执行）**：只写各项目内的 `项目/<编号>_<短名>/对接/交付/` 与该任务的 workdir（默认 `工作区/`，可指向系统外项目文件夹）。

**总控（`controller` 角色）**负责「任务登记 + 拆子任务」，不是执行者。发布任务后，控制台按 `协作/roles/controller.yaml` 的 `agent_id` 自动调用它（未绑定/不可用时依次回退 `openclaw-main`、`deepseek-harness`）；总控读人类原文，写任务单和 `subtasks.yaml`。总控只写本次任务 `对接/` 下的登记文件，不写审查、不执行子任务。

控制台不是协作角色；它的写入范围被硬性限制为 `项目/<编号>_<短名>/对接/idea.md`、`对接/task.yaml`、归档/恢复时的项目目录整体移动，以及 `协作/roles/**`、`协作/agents/**` 的角色与 Agent 配置，绝不写 `对接/交付/` 或 `对接/审查.md`，也不代写任务单/子任务。任务详情页可以显式派发一次 Agent 执行；执行器（`console/runner.py`）只额外追加该任务 `工作区/日志/run-*.log`，并维护 `协作/调度台/runner.status`、只追加的 `runner.history.jsonl` 和 `runner.lock`。发布登记复用同一把 `runner.lock`，用空 stdin 和超时调用总控，日志写 `工作区/日志/register-*.log`。macOS 菜单栏应用（`desktop/`）负责控制台进程与常驻守卫，写入 `协作/调度台/guard.status` 与只追加的 `journal.log`。

角色登记（`/roles`）与 Agent 登记（`/agents`）是路由与执行配置：角色可绑定本机已安装的 Agent CLI；任务详情页的「派给 Agent」把固定提示词交给一个已登记、`installed=true` 且当前可执行的 Agent。执行器同一时刻只允许一个写手，超时、失败或退出后释放锁；它不代写交付或审查。配置中的 `write_scope` 只是说明，不会覆盖本说明与八条防护规则。

角色“删除”会把 YAML 移到 `协作/roles/.archive/`，不删除原件。

## 每个任务一个项目目录

```
项目/
└── <编号>_<短名>/
    ├── 对接/
    │   ├── idea.md                 ← 发布时的人类原文；总控只读，不改写
    │   ├── task.yaml               ← 元数据：id/title/workdir/created_at/status…
    │   ├── 任务单.md               ← 总控登记时写入；看板据此显示
    │   ├── subtasks.yaml           ← 总控拆出的 2–6 个子任务
    │   ├── 登记完成.md             ← 总控最后写下的登记完成信号
    │   ├── 交付/                   ← AI-B 写入；多轮用 r1/、r2/……
    │   │   ├── r1/DONE.md          ← 该轮完成的唯一信号
    │   │   └── r2/DONE.md
    │   └── 审查.md                 ← reviewer 角色写入；头部含 审核角色 + Agent ID；执行方只读
    └── 工作区/                     ← 默认 workdir；AI-B 写入；实际产物（代码/文档/数据）
        └── 日志/
            ├── run-*.log           ← 执行器追加 stdout+stderr；不覆盖
            └── register-*.log      ← 总控登记输出
```

- 任务相关的**全部中间文件**都放在该项目目录的 `对接/` 内。
- 实际产物放在该任务的 **workdir**（默认同一项目的 `工作区/`，也可以是系统外项目文件夹），不要放回 `对接/`。workdir 记录在 `对接/task.yaml`。
- 任务编号以项目目录名的 `T<数字>` 前缀为准；控制台只扫描 `项目/*/对接/任务单.md`。
- 新建任务走「选项目文件夹 → 写想法 → 发布」：控制台先原样保存 `idea.md` 与 `task.yaml(status: registering)`，再由固定提示词的总控写任务单、`subtasks.yaml` 和 `登记完成.md`。登记完成后看板才出现该任务；失败可重试，不丢人类原文。
- 子任务模型在 `对接/subtasks.yaml`；可手动分发、审核或全自动推进。取消发布页的自动推进选项时，只登记，等待用户启动。

## 值班台 vs 工作目录

- **值班台** = 系统根（本仓库）。它只管理 `协作/`（角色、Agent、调度台）、`项目/`（任务与对接）、`归档/`、`console/`、`desktop/`；**不是 Agent 干活的地方**。Agent 不得向 `协作/` 写任何东西；产物只写 workdir（交付 DONE.md 除外）。
- **工作目录 workdir** = 每个任务自己的项目文件夹（绝对路径），是 Agent 的 cwd 与产物落点。发布页必须选择一个已存在的项目文件夹（原生选择框或手填绝对路径）；旧版任务和详情页仍可用默认 `项目/<编号>_<短名>/工作区/`。可指向系统外项目文件夹（例：`~/Documents/外汇量化交易`）。
- `task.yaml` 记录基础字段 `id`、`title`、`workdir`、`created_at`；T08 发布后还有 `status`、`controller`、`register_log`、`idea_sha256` 等登记字段。缺失时控制台自动生成。
- 交付仍写值班台的 `项目/<编号>_<短名>/对接/交付/r<n>/DONE.md`；执行器运行日志仍写值班台的 `项目/<编号>_<短名>/工作区/日志/`，**不写进外部 workdir**。
- 校验：绝对路径；非系统根本身；不在 `协作/` 及其子目录；系统根内只接受 `项目/<编号>_<短名>/工作区/`；发布页还要求目录已经存在。非法路径拒绝并说明原因。

## 三个约定

1. **只写自己的目录**：AI-A 只读并审阅 `对接/审查.md`；审查文件由 reviewer 角色绑定的 Agent 写（头部 `审核角色：角色名（Agent ID）` 与 `审查时间：…`）；AI-B（包括被派发的 Agent）只写本任务的 `对接/交付/` 与 workdir（默认 `工作区/`）；总控只写本次任务的 `任务单.md`、`subtasks.yaml`、`task.yaml` 与 `登记完成.md`；控制台只写 `对接/idea.md`、`对接/task.yaml`（及归档/恢复的目录移动）；执行器只追加值班台侧的运行/登记日志并维护调度台运行状态/历史/锁；菜单栏应用只写 `guard.status` 与追加 `journal.log` / `console.log`。互不覆写。
2. **`DONE.md` = 完成的唯一信号**：没有 `DONE.md` 即未完成。最新一轮按 `对接/交付/**/DONE.md` 的修改时间判定。
3. **旧版永不删除**：重交在同一项目内新建 `对接/交付/r2/`、`r3/`……；旧交付、旧审查不得删除或覆盖。

## 审查署名与推进停止

- **审查署名**：新审查的 `审查.md` 头部必须含 `- 审核角色：<role.name>（<agent.id>）`、`- 审查时间：…` 和实际结论。出现 `AI-A` 字样视为冒名：控制台拒收，并把 `审查.md` / `审核完成.md` 移入 `对接/审查历史/invalid-attribution-<时间>.md`；不算审核终态。历史审查（T24 之前）不改、按旧规则判定。
- **停止推进**：任务详情页「停止推进」或 `POST /advance/<编号>/stop` 由用户显式触发；控制台终止当前 Agent 进程组、等待推进线程收尾并释放 `runner.lock`，状态 `stopped`；停止后不会自动重新拉起；只有所属工作线程和进程组完成清理，才报告停止完成。若尚未收尾，页面继续显示正在停止。
- **推进预算**：默认最长 2 小时、最多 12 个子任务、最多 3 轮修订；超限停止为 `stopped_with_budget`，页面说明原因，同样释放锁。预算可用命令行参数或 `COLLAB_ADVANCE_MAX_*` 环境变量配置。

## 执行器（人工派发）

- 人工执行入口只有任务详情页的「派给 Agent」；UI 不能传入自定义提示词。发布/重试触发的总控登记是固定提示词的自动入口，同样受执行器锁约束。
- 派发对象必须是一个已启用、已绑定可执行 Agent 的角色，或一个已登记、`installed=true` 且当前可执行的 Agent。总控登记按 `controller` 角色绑定解析，未绑定/不可用时回退 `openclaw-main`、`deepseek-harness`。
- 执行器用固定提示词要求：先读值班台的任务单；**cwd = 该任务 workdir**，产物只写这里；交付仍写值班台 `项目/<编号>_<短名>/对接/交付/r<n>/DONE.md`；不得向 `协作/` 写任何东西，不得写 `对接/审查.md`、不得改其它项目、不加依赖、不删文件、不重启 8787。模板规则优先于任务单中的矛盾文字。
- 全局单实例锁 `协作/调度台/runner.lock`；同一时刻绝不允许两个写手。已有活锁时第二次派发被拒绝。主 CLI 退出后会先清理其遗留的后台进程组再释放锁。
- 执行器不是系统级沙箱；Agent 的最终权限取决于登记的 CLI 与工具配置。只应登记可信 Agent。
- 日志始终写值班台侧 `项目/<编号>_<短名>/工作区/日志/run-<时间戳>.log`，不写进外部 workdir；状态见 `协作/调度台/runner.status`，最近记录见 `/runs`。总控登记日志为同目录的 `register-<时间戳>.log`。
- 总控登记复用 `runner.lock`、空 stdin 与超时；登记结束前先把 `task.yaml` 收口为 `registered` 或 `register_failed`，再释放锁。
- 归档项目不能派发；正在执行或正在登记的项目不能归档。

## 八条防护规则

1. 只接对方的任务单/审查意见，**不得修改它们**。
2. 不得读取封存期数据。
3. 某些模块只读，不得触发其付费 API。
4. 不得连接券商、不得下任何订单。
5. **同一任务自动修正默认最多 3 轮**，统一读取 `协作/settings.json`（可用 `COLLAB_MAX_REVISE_ROUNDS` 覆盖）；中断后恢复同一轮不增加轮次。
6. 每次交付附 `DONE.md` + 测试结果；旧输出不得删除。
7. 规格确认、正式结论、真实资金 ⟹ **一律须人类批准**。
8. 发现规格矛盾 ⟹ **停下提出**，不得自行补规则。

## 状态与守望

控制台按以下顺序判定每个任务的状态：

1. 交接阻塞、运行中的分发/审核优先显示当前阶段；分发中显示执行中。
2. 审查必须具备明确可识别结论 + `审核完成.md`；新审查还需有效角色与 Agent 署名，才构成已通过或须修正。
3. 无审核终态时，任务级 DONE、全部子任务交付或无子任务时的工作目录产物构成交付证据。
4. 其它情况为待处理；中断的修订保留原轮次和上下文，可在详情页恢复。

调度台 `watch.sh` / `ack.sh` 的观察根是 `项目/*/对接/`（递归包含各轮交付）；`工作区/` 不参与唤醒扫描。

## 被叫醒后的标准流程

1. `ack.sh`（**立刻**，先于任何工作）
2. `since.sh`（看清改了什么）
3. 判断是「通知」还是「任务」；定位对应的 `项目/<编号>_<短名>/`
4. 若任务：读任务单全文 → 查防护规则 →（须修正时先 `rounds.sh check/bump`）→ 读 `task.yaml` 确认 workdir → 开工 → 产物写入 workdir，交付写入 `对接/交付/rN/` → 写该轮的 `DONE.md` → 记 `协作/调度台/journal.log`。经控制台派发的 Agent 还会由执行器自动记录值班台侧 `工作区/日志/run-*.log` 与 `runner.status`。
5. 守卫重挂由菜单栏应用自动负责；若菜单栏应用未运行，再手动重新挂 `watch.sh`

## 已弃用目录（只保留作历史档案）

以下旧目录**已弃用**，不再被控制台或调度台扫描：

- `协作/任务单/`
- `协作/交付/`
- `协作/审查/`

为遵守“旧版永不删除”，这些目录及其中文件原样保留。新的任务单、交付、审查一律写入 `项目/<编号>_<短名>/对接/`，不得再向旧目录添加内容。

调度脚本通过共享 `state.py` 从当前检出目录（或 COLLAB_ROOT）定位数据，内容哈希可识别同秒等长修改。快照对未变文件去重复用，旧版本保留。
